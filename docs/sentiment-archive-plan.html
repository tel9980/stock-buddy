情绪日报 · 归档中心方案预览 · 2026-09-02 · stock-buddy

目标：把「按日期归档 / 回溯任意交易日 / 导出单文件 HTML」从「能力已存在但用户找不到」推进到「归档可发现、可管理、可留存」。

先说结论：三项能力其实都已经实现了——导出路由、归档表、按日期回溯全都在线且可用。 真正的缺口是可发现性：系统里已经归档了 5 天，但用户无从得知，只能拿 DatePicker 盲猜日期， 猜错就触发 20 秒冷启动。下面先盘现状，再给补法。

四、分阶段实施

1
后端：归档目录接口必做
  • Repository::list_sentiment_daily(limit) → Vec<SentimentArchiveEntry>（date / generated_at / payload_bytes / covered_count / board_count）
  • GET /api/v1/sentiment/dates → 已归档日期列表，按日期倒序
  • covered_count 取法：每次反序列化 5 条 payload（约几毫秒）而非加冗余列——避免 schema 变更与迁移；条目数天然只有个位数到几十条
  • 可选：DELETE /api/v1/sentiment/daily?date= 删除归档，配合「重新计算」清掉坏数据
改动文件：crates/storage/src/repository.rs、crates/api/src/routes/sentiment.rs
2
前端：归档抽屉 + 日历标记必做
  • 工具栏加「归档 (N)」按钮 → Drawer 列出已归档日期（生成时间 / 覆盖只数 / 体积），点击秒开
  • DatePicker 用 antd cellRender 给已归档日期加橙底圆点
  • 选中未归档日期时弹确认条，给出实测预期耗时
  • 新增 api.listSentimentDates() 与 SentimentArchiveEntry 类型
改动文件：frontend/src/pages/MarketSentiment.tsx、frontend/src/api/index.ts
3
导出件服务端留存必做
  • export_daily 在返回浏览器下载的同时，写一份到 data/reports/sentiment-{date}.html
  • 归档抽屉的「⬇ HTML」直接从该目录取，命中则不再渲染
  • 目录可通过配置项开关，写入失败仅记日志、不影响导出本身（与现有 cache_if_complete 的容错风格一致）
改动文件：crates/api/src/routes/sentiment.rs
4
收盘后自动归档可选 · 依赖 scheduler
注意：scheduler crate 目前只有 2 行 stub（pub struct Scheduler;），要从零搭。 每交易日 15:30 自动生成当日日报并落库，让归档从「被动等用户触发」变成「主动积累」。 建议放在前 3 阶段验证稳定后再做。

五、风险与约束

项说明
数据库迁移无需迁移。sentiment_daily 已有 date / payload / generated_at 三列，目录接口纯查询即可
向后兼容全部为新增字段与新增路由，不改动现有 SentimentDaily 结构，前端已有功能不受影响
payload 解析开销归档条目数量级为个位数～几十条，每次反序列化约几毫秒；若将来归档上千天再改为冗余列
服务端留存体积单份 81–141 KB。按每交易日 100 KB 估算，一年约 25 MB，可接受；可加保留天数上限
冷启动并发压力现有并发 24、腾讯会限流。阶段 4 若做自动归档，需错峰并保留 is_degraded 守卫
建议节奏：阶段 1–3 一次做完并验证（归档可发现 + 可管理 + 可留存形成闭环），阶段 4 单独一轮。 这样每一轮都有可验证的交付物，符合你一贯的「先引擎、再进阶」分阶段验证习惯。
