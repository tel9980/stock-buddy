## AI 功能失效分析与修复

### 诊断出 3 个根本原因
1. **错误返回 HTTP 200**: 所有 handler 返回 `Result<T, String>`，Axum 将 `Err(String)` 映射为 HTTP 200 + `text/plain`。前端 SSE 解析器检查 `resp.ok` 为 true，尝试解析非 SSE 内容，静默失败 → 页面无任何反应，无错误提示
2. **日志只输出 stdout**: `tracing_subscriber::fmt().init()` 不写文件，后台运行时日志不可见
3. **DeepSeek 免费额度耗尽**: `free_quota_exhausted` (用量 506 万/限额 500 万)

### 修复方案
- **后端错误返回**: 所有路由 handler 错误类型从 `String` 改为 `(StatusCode, Json<ErrorResponse>)`，覆盖 quotes/kline/market/analysis/capital/limitup/dragontiger/finance/ai 共 9 个路由文件
- **双路日志**: 新增 `tracing-appender` 依赖，`main.rs` 配置 stdout + 文件双写，日志写入 `logs/stock-assister.log.YYYY-MM-DD`，注意保留 WorkerGuard
- **前端 SSE**: 新增 `parseErrorResponse()` 函数支持 JSON 错误解析，`streamSSE`/`streamPostSSE` 增加 Content-Type 检查，非 `text/event-stream` 响应正确触发 `onError`
- **前端 request()**: 同样支持 JSON 错误响应解析
- `.gitignore` 新增 `logs/`

## AI 报告 HTML/Markdown 渲染修复（字体偏大问题）

### 根因
- 后端 Prompt 要求输出 Markdown，但 LLM 实际返回 HTML（`<h1>` `<table>` `<strong>` 等）
- `react-markdown` v10 默认不解析原始 HTML，直接丢弃 `<h1>` 等标签 → 用户看到裸标签 + 未渲染的 `##` 文本，排版/字号失控

### 修复
- **前端**: 新增 `rehype-raw` + `rehype-sanitize` 依赖，创建共享组件 `frontend/src/components/MarkdownView.tsx`（react-markdown + remark-gfm + rehype-raw + rehype-sanitize）
- 三个 AI 页面（AiMarket/AiDiagnosis/AiChat）改用 MarkdownView 渲染，HTML 与 Markdown 双兼容且防 XSS
- **后端 Prompt**: `prompts.rs` 新增 `OUTPUT_FORMAT` 常量（禁止 HTML 标签、要求纯 Markdown 表格语法），注入到 diagnosis/market/prediction/chat/batch 全部 5 个 prompt
- **CSS 字号**: `.ai-report-content` h1/h2/h3 从 1.4/1.2/1.05rem 降到 1.25/1.12/1.0rem，base 0.92→0.9rem；`.chat-msg-content` h1/h2/h3 显式设为 1.12/1.02/0.95rem（之前未设导致继承浏览器默认 2em 偏大）

### 踩坑
- Rust 原始字符串 `r##"..."##` 与正文中的 `##`（如 `## 标题`、`# / ## / ###`）冲突导致 "unclosed delimiter" 编译错误；统一改为 `r#"..."#` 解决（正文 `##` 不与 `#"` 终止符冲突）
- OUTPUT_FORMAT 正文里的 `<h1>` 等标签也去掉尖括号，避免与 raw string 解析混淆

## Markdown 报告"显示差/像没解析"二次修复

### 根因（上一轮漏掉的点）
- `rehype-sanitize` 默认 schema 会**删除所有元素的 `style` 和 `className` 属性**（仅保留 `id`/`title`/`width` 等少量）。
- 当 LLM 返回 HTML（带 `style="color:red"`、`<div class="report">`、`<table style="width:100%">`）时，排版/颜色/表格宽度全被剥掉 → 报告看起来"未解析、排版崩坏"。纯 Markdown 其实一直能正常解析（已用 unified 管线在 node 中复现验证：h1/table/strong 等均正确生成 hast）。

### 修复
- `frontend/src/components/MarkdownView.tsx`：基于 `defaultSchema` 扩展 `displaySchema`，在 `*` 上放开 `className`/`style`，`a` 上放开 `target`/`rel`；保留 rehype-raw 解析 HTML，仍拦截 script/iframe/事件处理器。
- `frontend/src/index.css`：`.ai-report-content` 补充 `div` 间距、`pre`/`code` 代码块、`a` 链接、`hr`/`img` 样式，覆盖模型可能输出的各类元素。
- tsc -b 通过。

### 结论
- 纯 Markdown 与 HTML 现在都能完整渲染且保留样式；若仍"像没解析"，多为浏览器 HMR 未刷新或 LLM 仍返回异常内容，刷新页面即可。

## 修复龙虎榜数据为空

### 根因
- `crates/fetcher/src/eastmoney.rs` 的 `fetch_dragon_tiger` 用了**不存在的报表明名** `RPT_DAILY_BILLBOARDTRADING`，东方财富返回 `{"result":null,"message":"报表配置不存在"}` → 数据恒为空。
- 另：原代码引用的 `REASON`/`BILLBOARD_AMOUNT_RATE`/`AMPLITUDE` 字段在该报表中不存在（实际是 `EXPLANATION`/`DEAL_AMOUNT_RATIO`，且无振幅字段），且金额单位为「元」但模型/前端按「万元」处理。

### 修复
- 报表名改为 `RPT_DAILYBILLBOARD_DETAILSNEW`（curl 验证有数据，最新交易日 2026-07-31）。
- 字段映射：`EXPLANATION`→reason，`DEAL_AMOUNT_RATIO`→lhb_amount_ratio，去掉不存在的 amplitude(置0)。
- 金额（ACCUM_AMOUNT/BILLBOARD_NET_AMT/BUY/SELL）统一 ÷10000 转成「万元」；`TRADE_DATE` 只保留日期部分。
- 日期筛选归一化：前端选日期传 `YYYYMMDD`，后端转成 `YYYY-MM-DD` 再拼 `filter=(TRADE_DATE='...')`（接口按此格式匹配有效）；默认不传 date 走最新数据。
- cargo build 通过。
- 注意：前端 DatePicker 初始显示"今天"但实际展示最新交易日数据（默认加载不带 date）；后端需重启生效。

### 二次根因（真正导致"看不到"的原因）
- 第一次只改了报表名仍看不到，因为 `datacenter.eastmoney.com` 返回的响应带 `Content-Encoding: gzip` 但响应体并非合法 gzip，`reqwest`（gzip 特性未开）对 `.json()` 报 `Network error: error decoding response body` → 解析失败返回空。curl 能显示是因为 curl 自行处理。其余 push2 / datacenter-WEB 域名正常。
- 在 `fetch_dragon_tiger` 改为**每次请求加 `Accept-Encoding: identity`** 头（绕过 default_headers 对该头的限制，per-request 才生效）并改用 `.text()` + `serde_json::from_str` 本地解析。注：`default_headers` 里设 ACCEPT_ENCODING 对 reqwest 无效，必须 per-request。
- 同时数值字段由 `f64` 改为 `Option<f64>`：`#[serde(default)]` 只处理"字段缺失"，不处理显式 `null`，部分记录数值为 null（如涨停可转债），会导致 `invalid type: null, expected f64`。
- **顺带修复同域名的 `fetch_financial_indicators`（`RPT_DMSK_FN_MAININDICATOR`，`datacenter.eastmoney.com`）**：同样的 gzip + null 问题，已用相同方式修复（数值字段改 Option）。`datacenter-web.eastmoney.com`（融资融券）不受影响。
- 验证：临时 `#[tokio::test]` 真实网络跑 `fetch_dragon_tiger` 返回 count=100、首条 net/buy/sell/ratio 正确（元→万元换算对）；验证后已删除该测试（避免 cargo test 依赖外网）。
